### What version control is

Version control records changes to files over time. You can return to an older snapshot, see who changed what, and work in parallel without copying folders by hand.

### What you get from it

- History of every committed change
- Branches for experiments without breaking main
- Undo and compare when something stops working
- A shared remote (GitHub) so the whole team uses one source of truth

<RulesBox title="Why FTC and FRC teams use it">

- Several students can edit robot code without emailing zip files
- Autonomous and teleop changes stay traceable through the season
- You can roll back to code that worked at the last event
- Pull requests give mentors a place to review before merge

</RulesBox>

### How Git fits in

Each **commit** is a snapshot of the project. Git stores the full history locally. When you add a **remote** on GitHub, you push and pull those snapshots so everyone stays aligned. Git is the tool; GitHub is hosting and collaboration on top of Git.
