### Pull requests

A **pull request** (PR) asks the team to merge your branch into another branch (usually `main`). Review happens on GitHub before the merge.

### Why teams use PRs

- Proposed changes are visible in one place
- Mentors can comment line-by-line
- Discussion stays attached to the code
- Merge only after approval (if the repo is set up that way)

### Open a PR

- Push your feature branch: `git push origin your-branch`
- On GitHub, choose **Compare & pull request**
- Write a title and short description (what changed, how you tested)
- Request reviewers if your team uses them

### Review and merge

Reviewers read the diff, test locally if needed, and approve or request changes. Resolve merge conflicts by updating your branch from `main` and pushing again. After merge, delete the feature branch to reduce clutter.

### PR habits

One feature or fix per PR when possible. Say what you tested (sim, practice bot, etc.). Reply to review comments so the thread stays clear.
