### Introduction to FTC Path Planning Libraries

Path libraries generate smooth trajectories and help your follower stay on them. **PedroPathing** and **Road Runner** are two common FTC choices. Both pair with odometry; they differ in setup effort, features, and tuning workflow.

### What is PedroPathing?

PedroPathing targets FTC teams that want a smaller API and quicker first path. It covers basic following, localization hooks, and straightforward configuration without the full Road Runner stack.

### What is Road Runner?

Road Runner supports splines, velocity and acceleration limits, and tight integration with odometry tuning tools (including live tuning via dashboards). Many competitive teams use it; expect more Gradle setup and math up front.

### PedroPathing vs. Road Runner: Feature Comparison

| Feature | PedroPathing | Road Runner |
| --- | --- | --- |
| Ease of Setup | Very easy | Moderate/Complex |
| Path Types | Lines, arcs | Splines, lines, arcs, curves |
| Localization | Basic | Advanced (supports 2/3 wheel odometry) |
| Tuning Tools | Manual | Dashboard, live tuning |
| Documentation | Simple examples | Extensive, community-supported |
| Customization | Limited | Highly customizable |
| Performance | Good for most teams | Excellent, competition-proven |
| Best For | Beginner/intermediate teams | Intermediate/advanced teams |

### Which Should You Use?

Choose **PedroPathing** when you want working auto paths quickly with less infrastructure. Choose **Road Runner** when you need spline trajectories, strict motion constraints, or you are investing in full odometry and tuning tooling for competition auto.
