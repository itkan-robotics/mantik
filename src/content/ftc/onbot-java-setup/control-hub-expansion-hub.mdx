### Control Hub and Expansion Hub

The Control Hub runs your code and hosts WiFi for the Driver Station. The Expansion Hub adds motor, servo, and sensor ports when one hub is not enough.

See: [FTC Docs: Hardware Setup](https://ftc-docs.firstinspires.org/en/latest/hardware_and_software_configuration/index.html)

<RulesBox title="Key Features" subtitle="At a glance">

- Control Hub: Contains Android device, WiFi, and hardware ports.
- Expansion Hub: Adds extra hardware ports (motors, servos, sensors).
- Both connect via RS485 cable for communication.
- Both are powered by the robot battery.

</RulesBox>

### Wiring and connections

Link hubs with an RS485 cable. Power both from the robot battery. Plug devices into either hub.

See [FTC Docs: Adding an Expansion Hub](https://ftc-docs.firstinspires.org/en/latest/hardware_and_software_configuration/configuring/configuring_dual_hubs/configuring-dual-hubs.html).

### Sample HardwareMap Usage

```java
// Example: Accessing hardware on both hubs
DcMotor leftDrive = hardwareMap.get(DcMotor.class, "left_drive");
DcMotor rightDrive = hardwareMap.get(DcMotor.class, "right_drive");
Servo armServo = hardwareMap.get(Servo.class, "arm_servo");
DistanceSensor distance = hardwareMap.get(DistanceSensor.class, "distance_sensor");

// The names must match the configuration on the Driver Station.
// Devices can be on either the Control Hub or Expansion Hub.
```

### Configuring hardware in the Driver Station

In the Driver Station app, add each device and give it a name that matches your `hardwareMap.get()` calls.

See: [FTC Docs: Configuring Hardware](https://ftc-docs.firstinspires.org/en/latest/hardware_and_software_configuration/configuring/index.html)

<RulesBox title="Best Practices" subtitle="Dual-hub tips">

- Label all cables and ports for easy troubleshooting.
- Double-check wiring before powering on.
- Keep firmware up to date on both hubs.
- Use clear, consistent device names in configuration.

</RulesBox>
